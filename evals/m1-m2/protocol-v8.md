# M1/M2 regression protocol v8

V8 retains the unchanged 30-case corpus, three repository pins, agent/model
pins, arm order, calibrated binary predicates, isolated Claude judge profile,
complete hook capture, claim denominators, and milestone thresholds from v7.
Freeze source and binary SHA-256 values before the first scored invocation.
This is a disclosed regression, not an independent holdout.

## Corrections supported by v7 evidence

V7 completed all 30 pairs, but one control later phase reached the Claude turn
limit. Codex login shells and portable MCP configuration could select the older
`/usr/local/bin/cairn` instead of the frozen candidate. Its original traces and
judgments remain preserved as observations; they cannot certify candidate
behavior. This identity limitation also applies to earlier Codex regressions.

After ordinary setup, the runner pins treatment MCP configuration to the
absolute frozen candidate binary, sets an isolated ZDOTDIR and login profiles,
and checks shell resolution plus candidate SHA-256 before either actor starts.
Controls retain no Cairn hooks, managed instructions, or MCP server. Stateful
Cairn CLI calls in a control trace invalidate that pair; discovery/help do not.
This explicit MCP path is evaluation instrumentation: ordinary setup still
writes a portable command. The configured login shell is checked; this does
not attest every possible shell or indirect command an actor could launch.

Both arms receive the same 300-second process budget and, for Claude, 20 turns
(previously 180 seconds and eight turns). Inputs, models, thresholds, and arm
order do not change. No failed comparison is selectively rerun.

V7 delivered irrelevant implementation summaries alongside user decisions and
incident findings. Product guidance now keeps those findings concise, preserves
choices as decisions and trials as observations, and uses source locators
without appending code-path narratives or constants. Source-supported but
irrelevant propositions remain failures of delivered-claim quality.

## Evidence and scoring

Use a new database, isolated homes/checkouts, and a short protected output path.
Run every case once. Preserve all failed phases, unknown labels, full meaningful
traces, actual forwarded hook payloads, and server delivery snapshots. A failed
or malformed judge process may be retried in a fresh isolated process with the
original attempt preserved; never replace a valid judgment.

The same authorized independent Claude judge and frozen calibration apply;
original Laya/Astra/Claude results remain preserved. Reused fixture screening
is not a new accuracy estimate. Shared actor/judge model-family limitations,
unverified Codex provider identity, and instrumented latency remain disclosed.
Count all actually delivered semantic memory claims, including rejected seeded
hazards. Support/relevance and harmful endorsement are separate predicates.

Thresholds remain 80% useful application, 90% delivered claims both relevant
and supported, zero privacy leaks/high-impact harmful advice, 20% median fewer
repeated investigation steps on eligible control pairs, and treatment completion
no worse than control. Empty, incomplete, invalid, or unresolved affected
denominators are never a pass. Total read calls are not repeated investigation.
